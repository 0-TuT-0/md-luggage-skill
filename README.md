# md-baggage

用于 AI 协作开发的文档管理 Skill，当前版本 **v0.2.0**。核心是轻量提醒入口与文档管理内核：按需准备资料、保存有效结论、维护验证与经验；Matt 等开发技能保持独立。

安装与操作见 [Using-README.md](skills/md-baggage/Using-README.md)，包含“项目级安装＋个人采用”、全局安装、首次接入和更新。AI 指令入口为 [SKILL.md](skills/md-baggage/SKILL.md)。

## 安装范围与采用范围

安装位置决定工具在哪里发现 Skill，采用范围决定如何维护项目资料。**项目级安装也可以仅个人采用**，不必提交安装副本或修改团队公共入口。

- 默认个人采用：受管资料保存于 `docs/md-baggage/`，整套资料及个人项目安装副本通过本地 Git 排除规则留在当前仓库，不修改团队共享 `.gitignore`。
- 团队采用：有明确团队约定后，再按受管范围维护公共入口与共享资料。`private/` 始终不进入共享索引或版本控制。
- 首次接入询问一次，按授权建档；未获授权后不再主动询问，除非用户主动提出。用户级极简状态记录帮助跨会话保留选择，当前动作仍以本次授权为准。

个人模式中的 `share/` 表示适合后续协作的资料，并不表示已经发布或成为团队规范。旧规格、原生工具配置与团队测试保持其权威位置，迁移先给方案、确认后再执行。

## 接入项目后的资料结构

下列目录和文件按实际内容创建，不预建整套空文件。Skill 安装目录与资料目录分别管理。

```text
项目根目录/
├── README.md                     # 原有项目介绍与导航
├── AGENTS.md / CLAUDE.md          # 原有规范；个人接入默认不修改
├── .codex/ / .claude/             # 工具原生配置保持原位
├── .agents/skills/md-baggage/     # 可选的项目安装副本
└── docs/
    ├── 原有专题资料…              # 保留原来源与权威归属
    └── md-baggage/
        ├── share/
        │   ├── README.md         # 受管范围、项目约定与条件导航
        │   ├── modules/<模块>/   # 模块概览、契约与经验，按需拆分
        │   ├── features/<需求>/  # 一个可独立验收目标
        │   │   ├── README.md    # 目标、依赖、问题和资料入口
        │   │   ├── spec.md      # 按需；已有权威规格则引用原处
        │   │   ├── test.md      # 测试索引、执行方式与验证摘要
        │   │   └── tests/       # 按需；个人模式下为独立本地验证
        │   └── integrations/<场景>/
        │       ├── test.md      # 按需：真实跨功能连接的验证资料
        │       └── tests/       # 按需：相应场景的独立用例
        └── private/<议题或需求>/  # 临时探针、试验与原始过程
```

正文实际保存，导航及跨文档引用使用链接。临时重述已有资料可留在聊天；新决定、重要事实、关键未决问题和交接所需信息写回对应资料。

团队已有测试由 `test.md` 引用，不搬运、复制或为符合目录结构而重写。项目测试体系可可靠使用时沿用其位置；确需另建的独立个人用例仅作本地验证，不宣称团队 CI 或正式回归已有覆盖。稳定个人用例持续保留；一次性探针在收尾清理、恢复任务时检查，未决试验和复现证据保留。
