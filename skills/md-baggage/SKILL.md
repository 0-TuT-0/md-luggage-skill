# 开发文档管家

让接手需求的 AI 找到相关、有效、足够的资料，把上下文留给实施。核心是轻量提醒入口与文档管理内核；Matt 等开发技能保持独立，本 Skill 不编排其流程。

## 进入任务

1. 从用户请求确定项目、议题、阶段与已有授权。阶段明确时直接准备；存在会改变范围的不同解释时再澄清。概念问答只按需查资料。
2. 读取适用的根／局部 AI 入口，以及 `docs/share/README.md` 中本次有关的配置和入口。沿当前需求、阶段资料和真实依赖补读；缺少统一入口时转接入模式。
3. 选择下面一种主要文档工作，仅加载该分支需要的参考。有效上下文直接复用，同一任务只补新增依赖。个人过程和历史因具体追溯需要读取，不递归展开所有链接。

| 本次工作 | 何时读取 |
| --- | --- |
| 接入、盘点或整理既有文档 | [接入规则](references/onboarding.md) |
| 准备／恢复议题、同步决定与进度、检查冲突、维护或查阅相关经验 | [记录与权威来源](references/records.md) |
| 维护测试资料、回归或最终审核记录 | [测试与审核](references/testing-review.md) |
| 判断是否需要技能提醒，或准备实际产物交接 | [提醒与必要交接](references/routing.md) |

## 共同约定

- 项目文档固定使用根目录下的 `docs/share/` 与 `docs/private/`。共享资料可含状态明确的草案；个人过程不进入共享索引或版本控制。沿用适用项目规范；路径冲突或既有仅本地规则按接入方案处理。
- 在已授权阶段自动维护相关文档。关键决定确认后及时记，普通进度与引用收尾集中记；切题或交接前保存有效结论。未确认想法保持草案或未决状态。
- 一份当前目标规格、一处主要进度来源、一套权威可执行测试。目标、实际实现、测试、业务验收、提交和部署分别记录。新目标尚未实现时明确标出，相关旧验证不能证明新规则通过。
- 写前重读目标段和直接关联资料，局部修改；遇他人更新先协调并保留有效内容。写后检查本次差异、受影响引用与规则一致性。无法依据明确来源裁决的业务取舍保留为冲突。
- 文档工作不扩大到实现、运行测试、提交、合并或发布授权。迁移先给方案，经确认再执行；完整目标路径冲突提示开发者改名，不覆盖、合并或自动加后缀。

## 收尾

说明本次有效资料、实际更新和未决缺口；无有效变化时无需改文件或另建报告。检查本次受影响内容即可。

阶段或独立任务结束时仅检查提醒价值；有未处理文档工作或确需方法切换时，按提醒参考给一句建议。不为已维护资料或正在使用的合适技能重复提醒；嵌套使用由最外层统一输出，未决问题不自动推进阶段。

生成项目文件时，再读取相应模板：

- [项目 AGENTS](assets/AGENTS.md.template)：创建或增量维护公共 AI 流程与文档规则。
- [共享入口](assets/project-index.md.template)：建立最小配置与资料导航。
- [需求 README](assets/feature-readme.md.template)：建立需求短入口。
- [测试资料](assets/test.md.template)：维护功能或联调的范围、入口与验证摘要。

模板只生成有内容的部分，项目事实由现场调查和已确认决定填写。
