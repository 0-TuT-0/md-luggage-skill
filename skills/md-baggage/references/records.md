# 资料准备与维护

单议题准备、已确认变化同步和当前资料一致性检查时读取。

## 组织与权威

| 位置 | 职责 |
| --- | --- |
| 根 AGENTS.md／适用局部入口 | 公共流程、文档规则和关键约束；局部保存实际差异 |
| docs/share/README.md | 最小配置、导航与条件读取入口 |
| docs/share/modules/模块/ | 模块总览、公共规则／契约和需求索引，按需建立 |
| docs/share/features/需求/README.md | 一个可独立验收目标的入口、背景摘要和依赖 |
| 需求中的 spec.md | 已确认目标、行为、范围与验收；草案明确标注 |
| 项目约定的 tracker | 任务与实际进度；未拆任务时可由需求 README 承担 |
| 需求或联调的 test.md | 测试边界、执行方式和当前验证摘要 |
| docs/private/议题或需求/ | 个人过程与原始日志；有效结论提炼到共享资料 |

只在需要时创建实际内容。grill 前可用临时议题，不要求先有 spec 或拆完全部目标。小修正维护所属需求，避免为每次修改生成全套目录。

## 准备议题

定位目标、范围／授权、当前阶段的有效资料、事实来源、沿用术语、真实依赖和未决缺口。从短入口到所需正文／小节，无关需求、个人历史不随模块读入。

文档事实由 AI 调查，业务取舍交给用户。准备材料可呈现在当前对话或已有入口，不另造报告。

## 同步变化

回写对应权威正文，检查直接受影响的任务、验收和引用。共享草案不会仅因较新而取代已采用规则；状态简写即可，不强制完整元数据表。

确认的新目标更新当前 spec，标明待实现变化；进度反映实际工作，验证反映所测规则与实现。历史通过 Git 和必要变更说明追溯，确需基线时再保存明确标记的版本。

进度只维护一个主要来源：简单需求用 README，采用 tracker 后由 tracker 承担，README 改为导航。验证详情放 test.md，其他资料引用；索引避免复制规则和详细台账。

## 检查本次影响

核对相关引用可达、范围与状态明确、有无规则冲突、遗漏依赖或个人记录成为唯一依据。时间戳和文件名不足以裁决矛盾，依据已确认决定与适用范围判断，无法判断则保留冲突。

同一工作区写前重读、局部更新，不同分支合并时也检查语义冲突。围绕本次变化核对，不每次扫描全部历史。

## 经验与实现说明

首版仅采用存放原则：简短背景或实现流程放需求 README，确需独立阅读时再拆并给条件指针。实现说明解释关系、数据归属、状态和关键取舍，不复制源码。

个人探索留 private；已确认的项目可复用结论优先更新适用需求、已有规范或知识主题，注明适用范围与依据。跨项目经验升级另行决定，不自动写入全局 Skill。被替代结论指向当前来源。
