# 资料准备与维护

单议题准备、已确认变化同步、相关经验资料和一致性检查时，读取本次需要的小节。

## 组织与权威

| 位置 | 职责 |
| --- | --- |
| 原有根／局部 AI 入口 | 继续遵守工程规范；仅在相应授权下维护必要受管指针 |
| docs/md-baggage/share/README.md | 受管范围、最小配置、原权威来源与条件导航 |
| docs/md-baggage/share/modules/模块/ | 模块总览、公共规则／契约、需求与经验入口，按需建立 |
| docs/md-baggage/share/features/需求/README.md | 一个可独立验收目标的背景摘要、依赖、本轮实际记录和资料入口 |
| 当前权威 spec 或受管需求中的 spec.md | 目标、行为、范围与验收；已有团队规格不另复制，差异及草案明示状态 |
| 项目约定的 tracker | 任务与实际进度；未拆任务时可由需求 README 承担 |
| 需求或联调的 test.md | 测试边界、执行方式和当前验证摘要 |
| docs/md-baggage/private/议题或需求/ | 个人过程、临时探针和原始日志；有效结论提炼到对应正文 |

只在需要时创建实际内容。grill 前可用临时议题，不要求先有 spec 或拆完全部目标。小修正维护所属需求，避免为每次修改生成全套目录。

## 准备议题

定位目标、范围／授权、当前阶段的有效资料、事实来源、沿用术语、真实依赖和未决缺口。从短入口到所需正文／小节，无关需求、个人历史不随模块读入。

文档事实由 AI 调查，业务取舍交给用户。临时重述已有资料可留在对话；形成后续开发需要的新事实、决定、关键未决问题或交接信息时，在已授权范围内写回已有入口／正文，不以聊天或纯链接代替实际内容，也不每次另造准备报告。无建档授权时保持只读，不宣称已落档。

## 同步变化

在授权范围内回写对应权威正文，检查直接受影响的任务、验收和引用。个人受管资料记录本轮目标差异、适用约束、实施与验证事实，并引用团队来源；未获原正文维护授权时标待回写／待确认，不复制另一套现行规格。共享草案不会仅因较新而取代已采用规则；个人确认不自动等于团队采纳，状态简写即可。

确认的新目标更新其实际维护位置，标明待实现／待回写变化；进度反映实际工作，验证反映所测规则与实现。已纳入版本管理的历史通过 Git 追溯，个人忽略的资料不声称有 Git 历史；确需基线时保存明确标记的版本，不另建常态双份正文。

进度只维护一个主要来源：简单需求用 README，采用 tracker 后由 tracker 承担，README 改为导航。验证详情放 test.md，其他资料引用；索引避免复制规则和详细台账。

## 检查本次影响

核对相关引用可达、范围与状态明确、有无规则冲突、遗漏依赖或个人记录成为唯一依据。时间戳和文件名不足以裁决矛盾，依据已确认决定与适用范围判断，无法判断则保留冲突。

同一工作区写前重读、局部更新，不同分支合并时也检查语义冲突。围绕本次变化核对，不每次扫描全部历史。

## 经验与实现说明

简短背景或实现流程放需求 README，确需独立阅读时再拆。实现说明解释关系、数据归属、状态和关键取舍，不复制源码。个人探索与原始日志留 private，跨项目经验升级另行决定，不自动写入全局 Skill。

经验优先更新适用需求或已有模块主题，短内容可直接作为小节。按可独立采用的结论记录，同一主题可分别采用；存于模块层不代表所有功能都适用。

```markdown
### 经验主题或结论
- 适用条件：何时相关，哪些情况需要另行判断。
- 复用内容：可采用的结论、公共能力入口或相关文档。
- 依据与验证：来源、已验证场景、限制或待核实点。
```

在受管项目／模块／需求入口用“任务条件 → 文件或小节”的短指针导航，只读当前相关条目，不加载全部经验。原工程规范引用来源、记录本需求适用情况，不复制整份规范。尚未核实的原因保留为待验证判断。

发现潜在关联时先提示候选内容、适用条件和当前差异；需进一步判断时提醒使用 grill-with-docs，由开发者确认。采用、部分采用、不采用或待确认的结果记在当前需求并引用原文，不复制经验正文；条件未变不重复询问，当前选择不自动推广到新功能。已有明确适用的正式规范仍按规范执行。

### 按需复核

实际使用或相关变化时才核对适用性，不按固定天数判定过期；没有相关变化时不重复检查。需要时补一句状态及原因即可。

| 情况 | 处理 |
| --- | --- |
| 当前需求不满足条件 | 记录本需求不采用或部分采用，原经验保留 |
| 来源改名或移动 | 更新引用 |
| 关键实现、契约或业务前提可能影响结论 | 核对是否仍适用，无法确定则标待复核并说明原因 |
| 已有明确新结论替代 | 标已替代并指向当前来源 |

只复核已知受影响的采用记录，保留当时依据；不自动重开全部需求、改写业务决定或建立全局扫描机制。

## 临时资料清理

任务收尾时清理用途已结束的临时探针、无效重复试验和中间输出；恢复任务时检查已知遗留项。先保存有效结论，仅处理本任务及已知相关、已确定可丢弃的文件，不扫描全部 private，不按年龄统一删除，也不启动后台定时任务。

未决试验、仍需复现的证据和保留依据不明的内容继续保留。受管需求 tests/ 中后续仍需使用的稳定个人验证不是临时探针，不因任务完成而删除。清理遵循本次授权，说明实际处理及保留原因，无有效变化无需另建清理报告。
