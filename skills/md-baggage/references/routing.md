# 轻量阶段建议

需要判断阶段或独立任务收尾时读取。结合项目的目标、状态和授权判断前置条件，不复写完整技能目录。

先判断当前工作是否完成；关键问题未决时继续当前阶段，前置缺失时建议补齐，不机械向后跳转。

下列只是候选：推荐前读取目标 Skill 的实际 SKILL.md，核对可用性、输入、调用方式及项目约定。

## 跨技能交接

只核对当前目标技能，在项目配置或已有约定中明确三项：

- **必要输入**：本次目标、需求／任务入口、有效规格及该阶段实际需要的依赖；引用现有资料即可。
- **权威输出**：各类产物的唯一位置或 tracker；目标技能的默认路径不同也不另建第二份权威资料。
- **默认动作覆盖**：有已确认项目规则或当前授权依据的差异，例如定向测试、提交／外部写入范围。已有强制检查仍按项目约定处理，不因通用默认而静默省略。

交接随本次建议或调用说明给出，已有项目配置可直接引用，不另建交接报告或重写通用技能；需要新建约定时再参考[配置模板](../assets/project-index.md.template)。临时授权以本次请求为准，不沉淀为永久项目规则。

实际执行前确认当前工具能传递并遵守这些约定；缺少影响输出或权限的必要信息、或无法适配冲突时，明确相应执行缺口，保留候选建议，不回落到冲突默认。可从已有来源确定的直接复用，只有需用户取舍的才澄清；这些缺口不阻断普通资料准备。

用户直接使用某技能时，围绕其阶段准备／维护即可。测试驱动方法、具体架构和数据库设计交给相应能力；巨大模糊目标先明确探索需要，不在此展开全项目规划。

给当前最有用的一个建议，确有分支再给备选，说明理由和必要输入。目标缺失或工具不支持调用时，说明可用替代或给调用建议，不宣称已执行，也不自动安装技能。

建议不扩大实施、提交、合并或发布授权。项目 AGENTS 保留简版流程和文件规则，专项正文各有来源，不为每阶段另建状态文件。
