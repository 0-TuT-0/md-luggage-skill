# 项目接入与整理

首次接入、入口缺失或用户要求整理既有文档时读取。

## 盘点

识别适用 AI 入口、已有导航、规范来源、任务跟踪方式和相关技能配置。以文档和目录事实建立地图，不因接入就开展代码全量审计或推断完成比例。

配置可与 `docs/share/README.md` 合并，记录：项目与仓库范围、权威规范、模块／需求入口、唯一任务来源、可用技能与调用方式、测试入口适配状态、用户指定的最终审阅模型。对当前实际使用的技能，按[阶段建议中的交接规则](routing.md#跨技能交接)补充必要输入、权威输出与需覆盖的默认动作；已有明确约定可直接引用。未知字段仅在用到时补齐，不为未使用技能预建配置。

复用现有工具配置，不重复初始化工作流。多个 AI 工具入口共用项目事实；Skill 保存通用方法，项目保存实际采用的约定与差异。

## 新项目

在接入授权内建立有真实内容的根 AGENTS.md 和 `docs/share/README.md`。已有入口增量维护，保留局部约束。AGENTS 包含可执行简版流程和文档规则，长篇细则通过有读取条件的指针访问。

确认 `docs/private/` 被 Git 忽略且不进入共享索引。按需建立目录，不预建空的规格、任务或测试集。

## 既有项目

先提供整理方案，不先移动文件。按需列明源位置、用途与状态、权威归属、完整目标路径、受影响引用和工具输出路径、隐私／跟踪状态、冲突与需决定事项。

确认对应方案后再迁入已批准部分，修复引用、索引及相关技能／tracker 输出约定，使其指向同一权威位置。

重名按完整目标路径判定：不同需求的 spec.md 可以共存；目标已有文件或多源映射到同一路径时，提示开发者改名，冲突项保持待处理。日常更新受控文档与导入另一份文档是两种操作。

现有仅本地规则不会因新默认约定而失效。方案单独处理迁移、改变跟踪状态和对外发布范围；只建立索引时保留旧来源，不能标称已完成迁移。

`.gitignore` 不会取消已跟踪文件。此类资料单独说明处置范围与授权，验证实际跟踪状态并保留原内容。

## 完成条件

新项目有最小有效入口；既有项目未批准迁移时停留于盘点与方案。已执行部分可核对来源、目标、引用和状态，冲突与未迁移项保持可见。
