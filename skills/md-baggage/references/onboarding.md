# 接入选择与项目整理

开始／恢复实际项目文档工作时确认接入状态；首次接入、旧布局或用户要求整理时再读相应小节。安装范围和采用范围分别判断，自动选择 Skill 不表示项目已接入或有写入授权。接入选择只约束受管文档动作，不暂停用户已授权的其他工作，也不向其新增授权。

## 一次询问与个人状态

默认个人采用，团队采用须有明确团队约定。已有授权直接复用；用户明确要求接入或保存资料时，按该次范围执行，不再重复询问。

用当前用户的 `~/.md-baggage/projects.json` 保存一份极简映射：项目标识 → `asked`、`personal` 或 `team`。`asked` 表示已询问但尚未获授权，不表示拒绝原因。只保存这些选择，不保存业务资料、身份凭据、聊天或临时操作权限。

Git 项目标识使用 Git 公共目录的规范绝对路径（`git rev-parse --path-format=absolute --git-common-dir` 后解析真实路径），同一 clone 的 worktree 共用选择；非 Git 项目用已确认项目根的真实路径。独立 clone 为独立本地项目；移动后明确关联原记录，不凭同名目录猜测。

- 未有记录且本次工作需要接入时，先记录 `asked`，再仅询问一次是否建档及范围；回复前保持只读。明确仅讨论／只读的请求不触发接入询问。
- `asked` 且用户未主动重启接入／保存请求时，沿旧资料只读准备，不建受管目录、不改项目入口，也不换用提醒反复催促。
- 获授权后记录实际个人／团队选择，只在当前授权范围内建档和维护。状态不替代本次实施、提交、合并或发布授权。

写状态前重读并保留其他项目条目，完整写入后再替换原文件。状态损坏或不可读时保留原件，不重置为“未询问”；记录失败则说明跨会话记忆尚未可靠保存，不在项目中另建拒绝档案。

## 盘点与固定位置

受管资料根固定为项目根下 `docs/md-baggage/`；统一入口为 `share/README.md`，个人过程为 private/。按真实内容建立目录，不预建整套规格、任务或测试。

识别原生 AI 入口、已有导航、规范来源、任务跟踪、测试位置和必要技能约定。以文档事实建立地图，不因接入开展代码全量审计或推断完成比例。原有规范及相关需求仍按依赖读取，不因新入口而漏读。

最小项目配置与共享入口合并：受管范围、原权威来源、主要任务与测试入口、必要调用约定和用户指定的最终审核模型。个人偏好及临时授权不写成团队规则。实际产物交接再按[交接规则](routing.md#跨技能交接)核对输入、唯一输出和默认动作差异；普通提醒不要求补齐表格。

## 个人采用与团队采用

| 范围 | 资料与原生入口 |
| --- | --- |
| 个人 | `share/` 是适合整理复用的本地资料，不表示已发布；整个 `docs/md-baggage/` 本地排除。默认不改公共 README、AGENTS、CLAUDE 或共享工具配置；项目级个人安装的 Skill 副本也本地排除 |
| 团队 | 有明确采用约定后，share 可按授权纳入版本管理，private 排除；公共入口仅维护必要短区块，保留原规范，沿实际继承／导入链避免重复插入 |

个人 Git 排除优先写入仓库本地 `info/exclude`（用 `git rev-parse --path-format=absolute --git-path info/exclude` 定位），精确覆盖 `/docs/md-baggage/`；个人项目级安装另覆盖 `/.agents/skills/md-baggage/`。保留原规则，不忽略整个 .agents，也不为个人选择更改团队 .gitignore。非 Git 项目注明不适用。

先核对实际跟踪状态：ignore 不会取消已跟踪文件。已有团队跟踪的资料／Skill 不覆盖、不隐藏修改、不自动取消跟踪；保留现有来源，说明冲突并按具体授权决定范围。本地排除不构成访问隔离，同一物理目录中的其他会话仍可能发现 Skill。

需要原生入口指针时，先取得相应范围授权，再用[短区块模板](../assets/AGENTS.md.template)局部维护；标记只界定维护范围，不提高优先级。局部入口按实际位置计算链接。工具原生配置、规则和状态保持其原位，按文件用途判断共享或本地，不整目录迁入 docs。

## 既有资料与旧布局

新版不因安装／升级就迁移现有项目。识别旧 `docs/share/`、`docs/private/` 或其他权威位置，先列源位置、状态、完整目标路径、引用／工具输出影响、跟踪状态和待决定事项。新旧根并存时明确当前权威来源，不按目录名或时间戳切换，不创建第二份现行规格。

按确认的方案迁入批准部分，修复引用和输出约定；未批准部分保留原位。个人接入已有团队规格／测试时，保留其权威位置，受管目录保存本轮差异、实施记录、验证摘要和经验；未回写或未被团队采纳的变化明示状态。原团队正文的改动仍取决于本次授权。

重名按完整目标路径判定：不同需求的 spec.md 可共存；目标已有文件或多源映射同一路径时，提示开发者改名，不覆盖、合并或自动加后缀。更新所属正文与导入另一份资料分别处理。

既有仅本地规则继续有效；旧 private 仍有内容时保留原排除规则。迁移、改变跟踪状态和对外发布分别按授权处理。只建索引不能标称已完成迁移。

## 完成条件

有接入授权时建立最小有效入口，并核对正文、引用及实际 Git 排除状态；无授权保持只读及不再询问的选择。迁移只报告实际执行部分，冲突、原权威来源和未迁移项保持可见。
