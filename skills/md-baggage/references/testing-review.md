# 测试资料与最终审核

维护测试约定／结果或准备审核时读取。测试设计、编写与执行由当前已授权实施能力完成，本 Skill 维护资料与证据。

## 保存与范围

功能的 test.md 与可执行 tests/ 同存 `docs/share/features/<需求>/`。真实跨功能协作按场景放 `docs/share/integrations/<场景>/test.md` 与 tests/，需求 README 提供入口。

开发前以已确认验收列出本功能成功与必要失败行为。功能测试包含自身对依赖结果的处理；依赖自身的规则由对应功能负责。例如报名检查拒绝后不落单，资格计算归权限，真实连接放联调。

联调记录参与需求、协作关系、必要环境与入口，验证连接，不复制各功能整套测试。跨功能调用本身不使所有行为都归入联调，按约定职责选择。

test.md 使用 [三部分模板](../assets/test.md.template)。用例索引给短行为、规格依据及可执行位置；断言、造数和执行逻辑以 tests/ 为准。结果注明代码版本或工作区状态、范围、环境限制、通过／失败／跳过／未验证；不同范围分别说明，原始日志留 private 或已有测试系统。

测试只保留一份权威代码。接入时核对测试工具发现路径、依赖解析、运行目录和定向入口；工程适配由已授权实施工作处理。未核实接线时标明“执行适配未验证”，不能仅生成文件就宣称可运行。

## 定向验证与清理

| 变化 | 选择范围 |
| --- | --- |
| 本功能行为 | 对应已有用例 |
| 依赖结果或公共契约 | 受影响功能的对应用例 |
| 跨功能连接、数据传递 | 对应联调场景 |
| 仅排版、链接等说明 | 文档核对 |

结果适用于当前版本、范围和必要环境时复用，交付前确认本功能固定回归有效。影响不明时先调查，再说明扩大到哪些功能／场景，不默认全项目测试。既有额外检查在接入时明确适配，不静默省略。

正式用例从开发开始按约定保存，收尾精简为同一套固定回归。临时诊断、重复及过时测试在授权实施范围内清理；重写或重组先确认约定行为仍有有效覆盖、对应定向测试通过、入口有效，再移除替代项。既有测试迁移按接入方案执行。

## 最终审核

合并前，以明确 Git 比较基点和被审提交核对本次文档、实现与测试一致性。Skill 提供差异范围与必要依据，实际审核由可用审查能力执行。

从用户指定的默认／项目覆盖配置获取最终模型，记录实际使用模型。缺配置、模型不可用或工具无法调用时，标明“最终审核未完成”，说明缺口并请求指定或切换。替换模型需用户同意；普通验证、自评或模型名称本身不等于完成最终审核。

结论进入已有需求或审查记录，含基点、被审提交、范围、模型、问题和结论。未提交内容可草稿评审，不声称某个提交已覆盖这些变更。审核后再修改，按新增差异及其影响补审。

审核、业务验收、合并和发布分别记录，测试通过或本地提交不代替其中任何一项。
