# 测试资料与最终审核

维护测试约定／结果或准备审核时读取。测试设计、编写与执行由当前已授权实施能力完成，本 Skill 维护资料与证据。

## 保存与范围

功能 test.md 放 `docs/md-baggage/share/features/<需求>/`；真实跨功能协作按场景放 `docs/md-baggage/share/integrations/<场景>/test.md`，需求 README 提供入口。

已有项目测试保持原位，test.md 引用实际用例、执行入口与所验证行为，不为适配文档目录而搬运、复制或重写。项目测试体系清晰时，新增正式测试也由已授权实施工作沿原体系维护。

无法可靠定位／接入现有测试，或没有可用测试约定时，才选择独立用例位置并记录依据，不以目录风格不同触发重整。个人模式另建用例可放受管需求／联调的 tests/，整套随个人资料本地排除，明确为“个人验证”；稳定个人用例持续保留，不宣称团队 CI 或正式回归已有覆盖。团队模式新建 tests/ 的位置按已确认项目约定适配，已有代码仍不自动迁移。

开发前以已确认验收列出本功能成功与必要失败行为。功能测试包含自身对依赖结果的处理；依赖自身的规则由对应功能负责。例如报名检查拒绝后不落单，资格计算归权限，真实连接放联调。

联调记录参与需求、协作关系、必要环境与入口，验证连接，不复制各功能整套测试。跨功能调用本身不使所有行为都归入联调，按约定职责选择。

test.md 使用[三部分模板](../assets/test.md.template)，保存范围、短行为／必要预期、执行方法和实际摘要，不能只放链接。断言、造数和执行逻辑以所引用的原测试或独立用例为准；注明项目测试／个人验证及版本、范围、环境、通过／失败／跳过／未验证。原始日志留 private 或已有测试系统。

测试只保留一份权威代码。接入时核对测试工具发现路径、依赖解析、运行目录和定向入口；工程适配由已授权实施工作处理。未核实接线时标明“执行适配未验证”，不能仅生成文件就宣称可运行。

## 定向验证与清理

| 变化 | 选择范围 |
| --- | --- |
| 本功能行为 | 对应已有用例 |
| 依赖结果或公共契约 | 受影响功能的对应用例 |
| 跨功能连接、数据传递 | 对应联调场景 |
| 仅排版、链接等说明 | 文档核对 |

结果适用于当前版本、范围和必要环境时复用；项目正式回归与本地个人验证分别检查、分别说明。影响不明时先调查，再说明扩大到哪些功能／场景，不默认全项目测试。既有额外检查在接入时明确适配，不静默省略。

正式用例与稳定个人用例按各自位置维护，保留有效覆盖。临时探针按[收尾与恢复清理规则](records.md#临时资料清理)处理；已有覆盖需要重组时，由已授权实施先确认约定行为仍有有效覆盖、对应定向测试通过、入口有效，再移除替代项。既有测试迁移按接入方案执行。

## 最终审核

合并前，以明确 Git 比较基点和被审提交核对本次文档、实现与测试一致性。Skill 提供差异范围与必要依据，实际审核由可用审查能力执行。

从用户指定的默认／项目覆盖配置获取最终模型，记录实际使用模型。缺配置、模型不可用或工具无法调用时，标明“最终审核未完成”，说明缺口并请求指定或切换。替换模型需用户同意；普通验证、自评或模型名称本身不等于完成最终审核。

结论进入已有需求或审查记录，含基点、被审提交、范围、模型、问题和结论。未提交内容可草稿评审，不声称某个提交已覆盖这些变更。审核后再修改，按新增差异及其影响补审。

审核、业务验收、合并和发布分别记录，测试通过或本地提交不代替其中任何一项。
